# Notification Settings

## Module

Social

## Aggregate Root

NotificationSettings

---

# Purpose

The `notification_settings` table stores each user's notification preferences.

Users can control which notifications they receive and through which delivery channels.

The settings apply to all notification events generated by the application.

Each user has exactly one notification settings record.

---

# Responsibilities

- Store user notification preferences
- Control notification delivery
- Support multiple delivery channels
- Enable granular notification configuration

# Business Rules

- Every user can have only one settings record per notification type.
- Notification delivery is determined by the enabled channels.
- Disabled channels must never receive notifications.
- System notifications may ignore user preferences if marked as mandatory.
- Notification settings affect only future notifications.
- Existing notifications are not modified.

# Notes

Each user owns exactly one notification settings record for each notification type.

The combination of `user_id` and `notification_type` uniquely identifies a user's preferences.

Notification delivery follows this sequence:

1. A notification event is generated.
2. The user's notification settings are loaded.
3. Enabled delivery channels are determined.
4. Notifications are delivered only through the enabled channels.

This design allows new notification types to be added without changing the database schema. Only a new `NotificationType` enum value and corresponding default settings are required.
